## Proposed PR sequence

1. **Security containment.** Remove the default admin recipe. Add isolated access checks and harden profile access, the contacts directory, and generic email relay boundaries as separate security commits or narrowly scoped security PRs. Coordinate any live restriction with the environment owner and verify organizer and volunteer workflows.
2. **Regression tests and CI.** Replace stale auth coverage with tests against the active routes. Add isolated roster, permission, waiver, delivery, and clinic tests before shared workflow changes.
3. **Security and signup integrity.** Use separate security PRs for login-mail abuse controls and registration identity. Follow with a data-integrity PR for transactional capacity, waiver persistence, and idempotent retries.
4. **Reproducible environments and dependency patches.** Document and verify baseline migrations, runtime, environment names, and independent deploy steps. Patch dependencies in a separate PR with build and PDF-export smoke checks.
5. **Cleanup and refactor.** Keep generated files and obsolete scaffolding in a cleanup PR. Consolidate roster logic only after the regression tests pass. Track delivery visibility separately.

## Five-line summary

1. Profile policy and public directory access are the highest data-exposure risks. Live grants still need verification.
2. The generic email relay lacks function-side authorization, putting delivery quota and sender reputation at risk.
3. Signup can confirm a roster entry without reliably recording required waiver consent or enforcing capacity.
4. First PR to open is security containment for profile access, the public directory, and the default admin setup, with access checks.
5. Follow with a dedicated email security PR and add signup regression tests before restructuring the workflow.
